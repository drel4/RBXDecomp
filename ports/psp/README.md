# OpenRBX PSP — native runtime port (in progress)

Target: **PSP-3008 (64 MB)** with homebrew-capable firmware. No editor.

The previously packaged build is the accepted rendering milestone. Current source
also runs Lua, world physics and a local-player gameplay slice, but is **not a
completed full-engine port**: broader script compatibility and real obby acceptance
remain unfinished. Legacy XML RBXL geometry uses native PSP GU. Windows/MFC, Ogre, FMOD, and
the editor are not linked.

## Install

Copy the supplied `PSP/GAME/OpenRBX` folder onto the Memory Stick, giving:

```
ms0:/PSP/GAME/OpenRBX/EBOOT.PBP
ms0:/PSP/GAME/OpenRBX/content/character.rbxm
ms0:/PSP/GAME/OpenRBX/content/humanoidAnimate.rbxm
ms0:/PSP/GAME/OpenRBX/content/humanoidHealth.rbxm
ms0:/PSP/GAME/OpenRBX/places/Crossroads.rbxl
ms0:/PSP/GAME/OpenRBX/places/RenderTest.rbxl
```

Launch OpenRBX PSP from the PSP Game menu. Pick a place with D-pad and Cross.
Add your own **XML-format** `.rbxl` or `.rbxlx` files to `places/`. Circle browses
to a parent folder. Modern binary RBXL is detected and rejected with an explanation.

## Controls

For local Windows emulator checks, run this from the repository root:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ports/psp/tools/run_ppsspp.ps1
```

It starts the installed development PBP in a normal window.
Do not start PPSSPP v1.20.4/D3D11 minimized:
on the development machine this reproducibly leaves a blurred background even
after restoring, although simulation continues. Close that emulator and launch
normally. This is an emulator startup issue, not evidence of PSP rendering.

| Control | Action |
| --- | --- |
| Analog stick | Move character relative to camera |
| D-pad up / down | Camera pitch |
| D-pad left / right | Zoom in / out |
| L / R | Orbit following camera |
| Cross | Jump (browser: open) |
| Circle | Browser: parent folder |
| Triangle | Reset following camera |
| Square | Reset character; automatic respawn after three seconds |
| START | File browser / return to loaded scene |
| SELECT | Toggle HUD |
| HOME | Normal system exit |

## Implemented

- Streaming XML loader: no DOM; the ongoing runtime port now retains bounded
  script source, instance hierarchy, typed properties and referent links.
- Workspace filtering; preserves world positions, rotations, sizes, legacy
  BrickColors, transparency, and box/ball/cylinder/wedge geometry.
- Original engine BrickColor palette, generated by `tools/generate_palette.py`.
- Low-poly balls/cylinders, pre-baked flat lighting, one retained vertex buffer,
  CPU frustum culling, and load-time subdivision of large faces for PSP clipping.
- GU-rendered file picker and text; 16-bit double-buffered color and depth in VRAM.
- **30 FPS cap**, paced by two VBlanks per completed frame; FPS/frame-time/heap HUD.
- Main CPU VFPU matrix transforms through PSPSDK GUM. No Media Engine offload yet.

## Memory and packaging

- `PSP_LARGE_MEMORY=1` requests the extended user memory partition; the packaged
  `PARAM.SFO` must contain **`MEMSIZE=1`**.
- A **32 MiB heap budget** leaves headroom for the module, SDK, stacks, and future
  gameplay. This is reserved heap capacity, not a claim that the app uses only the
  live allocations displayed by the HUD.
- Previously packaged viewer Crossroads: **1,749 world parts**, **27,504 triangles**, approximately **1.42 MiB**
  retained scene allocations after large-face subdivision. The heap HUD includes
  additional live allocations, not GPU VRAM or all process/OS memory.
- Current development runtime with physics and copy-on-write snapshots: Crossroads
  reaches approximately **8.82 MiB live heap** after its Lua regeneration backups
  are cloned and expired projectiles remove themselves. Cached initial scene
  accounting is **7.22 MiB**. These are
  PPSSPP 64 MB measurements, not physical-device measurements or total OS memory.
- Loader caps: 8,000 visible parts, 600,000 vertices (9.6 MB), 64 MB input files,
  192 XML levels; oversized/unsupported places show an error instead of loading
  without a bound. The previous scene is freed before the next load.
- `BUILD_PRX=1`: **EBOOT.PBP contains a relocatable MIPS PSP PRX**, not a static
  ELF executable. The SDK produces intermediate link files, but no raw `.elf`
  belongs in the install package.

The build uses [PSPSDK's PRX/PBP and memory request rules](https://github.com/pspdev/pspsdk/blob/master/src/base/build.mak)
and [native GU/GUM APIs](https://pspdev.github.io/pspsdk/group__GU.html).

## Build

With PSPDEV on PATH:

```sh
cd ports/psp
make -j4
python3 tools/verify_pbp.py EBOOT.PBP
```

Or, in this directory on a Linux build machine with the existing PSPDEV image:

```sh
sh build-remote.sh
python3 tools/verify_pbp.py EBOOT.PBP
```

No Windows source/build settings need changing. The separate target does not alter
the desktop client's 240 Hz physics or rendering behavior.

The install archive also includes the matching target sources in `source/`;
run `make` directly in that folder. The generated palette is included, so only
regenerating it needs the full OpenRBX repository. `BUILD-INFO.json` records the
toolchain image and artifact hashes. `PSPDEV_IMAGE` can select a pinned image
when using `build-remote.sh`.

## Verification

```sh
sh tests/build-host.sh
./scene_check places/RenderTest.rbxl /path/to/Crossroads.rbxl
```

The host tests exercise real scene geometry plus malformed files, CDATA/comments,
binary-file detection, invalid sizes, Workspace filtering, and allocation limits.
`verify_pbp.py` checks the actual PBP/SFO and PRX header, including `MEMSIZE=1`.

The PBP has been booted in **PPSSPP 1.20.4, 64 MB PSP model**, with file selection,
Crossroads, primitive rendering, camera controls, and repeated place switching.
Emulator results are not a measurement of frame rate on a physical PSP-3008;
the physical device still needs testing.

## Original packaged viewer limitations

Physics/collisions, player control/spawning, Lua place scripts, multiplayer, audio,
textures/decals/studs, arbitrary MeshParts, and modern binary RBXL. This means obbies
are viewable but not playable yet. Media Engine scheduling and shared-memory/cache
coordination are future work; no kernel ME module is included or required here.

## Active playable-client port

See `PROGRESS.md` for the full goal and acceptance gate. The installed/archive
viewer remains the previously accepted rendering milestone until integrated
gameplay has been validated. Current source starts real Workspace place scripts,
binds inherited property defaults, Vector3/CFrame values and yielding signals,
and updates GU geometry from instance mutations. The development client now
creates Players.LocalPlayer, clones the actual six-part character, builds the
original joint frames, runs its real animation/health Lua, follows the character,
and supports movement, jumping, death and three-second respawning. Player APIs
include CreateLocalPlayer, LoadCharacter, GetPlayerFromCharacter and TakeDamage.
This is an integrated vertical slice, not completed compatibility with all games.
The basic world solver runs at fixed 240 Hz with real
gravity, primitive collisions, rigid surface/Weld assemblies, sleeping and
contact-to-Lua Touched. It is not a complete replacement of every engine solver:
angular contact impulses, breakable/spring/hinge constraints and high-speed CCD
remain unported.
Class recognition is not an implementation of all class behavior. For example,
the Crossroads rocket script still reports an unsupported Sound `play` method.

`places/ScriptRenderTest.rbxl` is a Lua/GU integration fixture (moving/rotating,
fading block), not a substitute for the required real-place gameplay acceptance.
It and Crossroads were run in the 64 MB emulator. Host regression tests cover
native-to-Lua Touched delivery, yielding Connect/Wait callbacks, typed Changed,
transform algebra and bounded geometry updates. `PhysicsRenderTest.rbxl` also
exercises falling bodies and a place script reacting to physical contacts.

Current Crossroads source uses copy-on-write property snapshots for independent
clones: measured steady heap dropped from 13.77 to **8.82 MiB** in the 64 MB
emulator with physics enabled. Settled physics costs about **1.2 ms/frame** there.
These are development/emulator measurements, not physical PSP guarantees. The
generation-checked arena now reclaims detached objects without invalidating
Lua-held backups. Repeated Crossroads respawns passed bounded-memory tests; see
Phase 5 in PROGRESS.md. Respawning still causes a brief full-world rebuild hitch.

### Reproduce emulator profiling

For an owned PPSSPP instance, enable `RemoteDebuggerOnStartup=True`,
`RemoteDebuggerLocal=True` and `RemoteISOPort=24689` in its configuration. Keep it
in the 64 MB PSP model. Generate a symbol map with the same build's
`psp-nm -n openrbx_psp.elf > symbols.txt`; the ELF is a build intermediate, not
the runnable release. The test helper requires Python's `websockets` package.

```sh
python tools/ppsspp_check.py button cross
# After loading/settling the place:
python tools/ppsspp_check.py --symbols symbols.txt profile
python tools/ppsspp_check.py --symbols symbols.txt respawns 20 --steady
python tools/ppsspp_check.py --symbols symbols.txt steady
```

The helper sends emulator controller events, not system keystrokes. It reads a
versioned, pointer-free diagnostic snapshot (`profile.h`) from the matching PRX:
frame rate, live heap, instance counts, collection/physics cost and player state.
It verifies fresh characters, stable Player identity, bounded memory and no new
runtime/Lua errors. An existing unsupported-script error is reported separately.
See [ME-INVESTIGATION.md](ME-INVESTIGATION.md) for the ME feasibility review.

`make` stages the repository's existing Lua 5.1.1 under ignored `vendor/` for
cross-building. `tools/stage_lua.py` preserves the engine's C++ exception-based
VM and applies three checked portability fixes: remove Boost-only thread-count
extra space (owned by ScriptRuntime), add modern noexcept declarations, and make
the nullable upvalue conversion defined. Original desktop sources are untouched.
Standalone source bundles must include the staged vendor directory and its Lua
copyright notice. No separately downloaded replacement VM is used.
